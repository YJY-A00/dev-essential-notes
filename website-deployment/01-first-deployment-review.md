# 第一次部署复盘：暑假初版网站

## 1. 实践背景

暑假期间，我尝试从零搭建个人网站。在实践过程中，我逐步接触域名、云服务器、Linux 系统、Go 后端、MySQL 数据库和 Nginx Web 服务，并完成了初版网站的部署。

这次实践的意义不仅是让网站能够访问，也让我开始理解一个 Web 应用从服务器环境到前后端服务的基本组成。

## 2. 已知技术环境

## 3. 部署链路理解

当时网站的基本请求链路可以概括为：

```text
用户浏览器
    |
    | HTTP / HTTPS
    v
Nginx
    |                         |
    | 静态资源请求             | API 请求
    v                         v
HTML / CSS / JavaScript     Go 后端服务
                                |
                                v
                            MySQL 数据库
```

Nginx 对外提供 Web 入口：静态资源请求由 Nginx 返回，API 请求转发给 Go 后端；Go 后端负责业务处理和数据库访问。

## 4. 实践中形成的认识

- 服务器能够安装软件，不代表公网已经可以访问服务，还需要检查云平台安全组和系统防火墙。
- 后端程序能在本地运行，不代表它已经正确构建并能由 Systemd 管理。
- Nginx 配置需要区分静态资源路径和 API 路径。
- 浏览器显示异常时，需要区分文件编码、HTTP 响应和浏览器缓存等可能因素。
- 网站上线涉及应用部署，也涉及域名解析、HTTPS 和备案等事项。

## 6. 复盘

第一次部署让我第一次把 Linux 服务器、后端程序、数据库和 Web 服务联系起来。过程中遇到的问题也让我意识到，部署不是简单执行安装命令，而是需要理解服务之间的依赖关系，并根据日志和实际访问结果逐步定位问题。
